# Jarvis 1.3 — real Mac access from the phone

Phone access must support the same Mac app/file/task capabilities as desktop voice. The earlier phone transport reached the task queue, but had no Mac picture and local visibility questions could receive a generic disclaimer without a tool call. The 1.3 worker receives a fresh Mac observation before local work, explicit app/file/tool capabilities and instructions to inspect actual screen content. The Mac read tool can return a screenshot as well as accessibility text. Voice receives the server-selected environment initially and after changes during the call. The selected target is still enforced by the companion; cloud tasks do not silently switch to Mac control.

The phone now defaults to the Mac and remembers the selected environment. A **Mac** tab shows the worker's current app window or the app in front. Manual takeover supplies click, text and named keys to the pictured window, with zoom and refresh. Active Mac work must be paused first. Each phone uses an independent Mac executor/capture state; stale or another device's frames are refused, input invalidates the frame and request IDs prevent repeat delivery. Revocation removes device screen state as well as its voice room. Screens remain memory-only and the gateway keeps its existing cookie/origin protections and HTTP allowlist.

The real-machine check found that the background manual-input path could report an attempt without an observed change. Phone manual controls now explicitly use foreground delivery to the selected window. Background agent/desktop behavior remains separate. Concurrent capture files also use a unique executor identity instead of one path per process.

Tailscale continues to provide the private HTTPS transport. Changing tunnel vendors would not fix missing application tools or an agent that failed to inspect them. Other trusted HTTPS relays remain possible with the same paired gateway. The Mac must stay awake, unlocked for relevant interactions and running Jarvis with Cua Driver's permissions. Physical iPhone audio still requires human testing.
